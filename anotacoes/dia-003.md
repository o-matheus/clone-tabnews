### A mesma fundação: Node.js e NVM

O Node.js foi apresentado como a fundação para executar JavaScript no ambiente de desenvolvimento e de produção. Usar a mesma versão do professor ajuda a reduzir diferenças entre os ambientes.

| Tecnologia | Versão indicada na aula ou usada no estudo |
| --- | --- |
| Node.js | LTS Hydrogen; versão usada pelo estudante: 18.20.8 |
| Next.js | 13.1.6 |
| React | 18.2.0 |
| React DOM | 18.2.0 |

Hydrogen era a LTS indicada no contexto histórico da gravação. As versões acima registram o contexto do curso, sem afirmar que sejam as versões atuais mais recentes.

Comandos discutidos:

```sh
nvm ls
nvm install lts/hydrogen
nvm use
node -v
```

- `nvm ls` lista as versões instaladas; `nvm ls-remote` lista versões disponíveis para instalação.
- `nvm install lts/hydrogen` instala uma versão da linha Hydrogen.
- `nvm use` lê o `.nvmrc` e seleciona a versão naquela sessão do terminal. O comando correto é `nvm use`, não `npm use`.
- `node -v` permite conferir a versão ativa.

### Separação entre projetos e o arquivo .nvmrc

O estudante já teve problemas ao usar uma versão antiga do Node em um projeto Angular que precisava de uma versão mais recente. Por isso, quis manter o clone do TabNews na versão do curso e os outros projetos em versões adequadas a eles.

O `.nvmrc` registra a versão desejada para o projeto e comunica essa escolha a outros desenvolvedores. Neste repositório, seu conteúdo é `lts/hydrogen`: ele seleciona a linha Hydrogen, em vez de fixar um número exato como `18.20.8`.

O sufixo `rc` foi associado no relato a “run commands”, também encontrado em nomes como `.bashrc` e `.vimrc`. No caso do `.nvmrc`, o conteúdo é uma indicação de versão para o NVM, não um script de comandos.

Cada terminal tem sua própria sessão. Executar `nvm use` em um terminal não troca automaticamente a versão em outro terminal já aberto. Sem integração automática, é necessário repetir `nvm use` ao iniciar uma nova sessão de trabalho no projeto.

O estudante confirmou que `node -v` mostrou `18.20.8` no terminal do projeto e relatou `24.21.0` no outro terminal. A segunda versão foi registrada conforme o relato, sem verificação independente de sua numeração ou de ser a mais recente.

O professor também mostrou `nvm alias default <versao>` no Codespaces para manter a escolha ao reabrir o ambiente. Esse alias define o padrão do NVM para novas sessões daquele usuário/ambiente; ele não é restrito à pasta do projeto nem somente ao terminal atual. Para a separação desejada pelo estudante, a solução usada foi `.nvmrc` com `nvm use`, sem precisar mudar o alias padrão.

### npm, package.json e package-lock.json

O npm é um gerenciador de pacotes usado no ecossistema Node.js para instalar e gerenciar código reutilizável.

`npm init` cria o `package.json`, que registra informações do projeto, scripts e declarações de dependências.

- **package.json:** declara as dependências e as versões ou faixas permitidas. Neste projeto, aparecem `^13.1.6` para Next e `^18.2.0` para React e React DOM. Essas faixas permitem determinadas atualizações compatíveis; o arquivo não atualiza pacotes sozinho.
- **package-lock.json:** registra a árvore de dependências resolvida, incluindo versões exatas, para permitir instalações reproduzíveis. Ele pode ser atualizado por operações do npm; não é uma cópia permanente apenas da primeira instalação.
- A versão do Node é gerenciada separadamente pelo NVM; não é determinada pelas versões de Next ou React no `package.json`.

Essas precisões sobre NVM e lockfile complementam o relato com a documentação indicada nas referências.

### Respondidas

**Como usar a versão do Node do curso sem afetar outros projetos?**

Registrar a versão no `.nvmrc` e executar `nvm use` na sessão do terminal do projeto. O estudante confirmou que a separação entre terminais funcionou.

**É necessário executar nvm use em toda nova sessão?**

Sim, por padrão. A versão já instalada não precisa ser reinstalada a cada sessão.

**O que faz npm init?**

Cria o `package.json`, com informações do projeto, scripts e declarações de dependências.

**Como foi resolvido o conflito de dependências?**

Durante o processo, apareceu um aviso ou erro relacionado a `ERESOLVE`, com mensagens como `npm warn ERESOLVE overriding peer dependency` ou `Could not resolve dependency`.

A orientação recebida apontava uma possível instalação anterior de versões diferentes. Essa hipótese não foi verificada independentemente. O estudante relatou ter removido `node_modules` e o lockfile e reinstalado as versões indicadas, conseguindo continuar o tutorial:

```sh
rm -rf node_modules package-lock.json
npm install next@13.1.6 react@18.2.0 react-dom@18.2.0
```

Esses comandos registram a solução aplicada naquele contexto. A pasta removida foi `node_modules`, não a instalação do Node.js. Remover o lockfile faz a árvore de dependências ser resolvida novamente.
