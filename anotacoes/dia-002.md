## Principais conceitos

### Git e GitHub

O professor usou a analogia de um arquivo de vídeo `.mp4` e do YouTube: o arquivo representa o lado local associado ao Git, enquanto o YouTube representa a plataforma associada ao GitHub.

Na explicação introdutória da aula, o lado do Git foi associado a uma pasta com os arquivos do projeto. Essa é uma simplificação: Git é o sistema de controle de versão que permite acompanhar o histórico de alterações desses arquivos.

O GitHub foi apresentado como uma plataforma para hospedar e distribuir repositórios, com recursos de colaboração e uma dimensão de rede social:

- As contas agrupam repositórios e podem funcionar como uma vitrine do trabalho da pessoa.
- É possível seguir outras pessoas e acompanhar suas atividades na página inicial.
- Entre as atividades mencionadas estão criar repositórios, comentar em projetos e seguir outras pessoas.
- A plataforma permite sugerir melhorias em projetos.

### TabNews: um projeto grande também começa vazio

Segundo os números apresentados pelo professor na aula de 2023, cerca de três meses após a inauguração, o TabNews tinha:

| Indicador | Número relatado |
| --- | --- |
| Visitas | Mais de 500 mil |
| Visualizações | Mais de 3 milhões |
| Inscritos | 27 mil |
| Publicações | 8 mil |
| Respostas | 34 mil |

Esses números são históricos, conforme o relato da aula, e não representam estatísticas atuais.

O TabNews foi apresentado como um projeto construído por Filipe Deschamps com outras pessoas. A mensagem central foi que, apesar do tamanho alcançado, ele também começou como um repositório vazio no GitHub.

### Criação e nome de um repositório

O professor orientou acessar a conta do GitHub e criar um repositório, apresentando informações como proprietário e nome.

- O nome do repositório funciona como um slug na URL.
- O nome da conta proprietária e o nome do repositório compõem o endereço de acesso: `https://github.com/proprietario/nome-do-repositorio`.
- A recomendação apresentada foi escolher um nome curto e memorável, se possível com uma palavra-chave relacionada ao tema do projeto.
- O dia também abordou dicas de SEO para facilitar que o projeto seja encontrado na internet; o relato não detalha outras técnicas.

O professor mencionou que a forma de lidar com branches e sua performance teria diferenciado o GitHub de outras plataformas, mas não aprofundou a afirmação. Esse ponto ficou registrado como uma questão a esclarecer.

### Função, estética e escolha de ferramentas

O professor comentou que defender um sistema operacional ou editor como o melhor pode gerar discussões pouco produtivas.

Na distinção apresentada, a **função** corresponde ao que será feito e a **estética** à forma como isso será apresentado. A orientação foi prestar atenção primeiro à função e depois escolher a apresentação que mais agrada.

**Reflexão do estudante:** quando as ferramentas atendem à mesma função, a escolha pode depender do costume ou da preferência de cada pessoa.

### Ambiente de desenvolvimento

Para desenvolver uma aplicação, foram destacadas duas necessidades básicas: um lugar para escrever código e um lugar para executá-lo.

As ferramentas mencionadas para a configuração inicial foram VS Code, Node.js, NVM e Docker. O NVM foi apresentado como uma forma de alternar a versão do Node.js. PostgreSQL e outras ferramentas seriam acrescentados conforme a necessidade ao longo do curso.

As aulas extras apresentaram duas possibilidades de ambiente:

- **Pelo navegador:** abrir o repositório no GitHub, clicar em **Code**, acessar **Codespaces** e solicitar a criação de um espaço de desenvolvimento.
- **Localmente:** seguir a configuração específica de Windows com WSL, Linux ou macOS. As orientações relatadas incluem instalar Node.js, NVM, Docker e VS Code, além de configurar uma chave SSH para facilitar a conexão com o GitHub.
